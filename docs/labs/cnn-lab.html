How a convolutional layer works

A convolution is one small dot product, repeated at every position

  1. A moving dot product

    The top-left cell of Output 1 multiplies the top-left 3×3 block of the input by Filter 1, cell by cell, and adds the nine products. The next cell does the same one column to the right. The X gives 3 on the diagonal because all three diagonal pixels line up with the filter's three ones. To follow along in Excel, tick "Show spreadsheet cell names" in Part 1.

  2. Locality and weight sharing

    Each output looks only at a 3×3 neighbourhood (locality), and every output uses the same nine weights (sharing). The filter is a pattern detector that is checked everywhere, so a diagonal stroke is found wherever it sits.

  3. Pooling tolerates small shifts

    A max pool keeps the largest value in each block. In Part 1 the max pool takes the largest value of a whole feature map, so it reports "a diagonal is somewhere" and ignores where. A 2×2 pool, as in Part 2 and Part 3, forgives moves of about one pixel; the dense layer after it still cares about position.

  4. Dense layer, then softmax

    Each class score is a weighted sum of the pooled values, and softmax turns the scores into probabilities that add to 1. The sheet's network scores the X 3, 3 and 3.6, so X wins with only 0.477, and it has no class for +. The extended network adds line filters and a fourth class, and its weights compare evidence: X = 1.5·(both diagonals − both lines). Every preset then wins by 3 points, about 91% or more.

What the sheet's second half was meant to do

Its formulas describe image → conv 1 (two maps) → conv 2, where each output adds a 3×3 filter over map 1 and another over map 2 → 2×2 max pool → one dense output, the sum of weights times pooled values over both channels.

In the file the image and the conv 1 maps are gone, and most conv 2 cells show #N/A, so the dense output shows #N/A too. Part 2 rebuilds that pipeline with a hand-drawn 7, the sheet's Part 1 filters for conv 1, its random conv 2 weights and its dense weights. The sheet's dense weight blocks are 12×13; a 24×24 map pools to 12×12, so the last column of weights (EL) has no partner and is left out.

What the training data is

The digits in Part 3 are simulated: each is a font character drawn on a hidden canvas with random font, weight, size, rotation, stroke width, a small shift and some noise, then scaled and centred the way MNIST digits are. They are cleaner and more regular than handwriting, so accuracy here is not an MNIST result. Your own drawings are harder.

Try this in class

  1. In Part 1, switch to the Spreadsheet network and load the +. Ask the class which of its three classes wins before you look, then read the All patterns table. Switch to the Extended network: how sure is it about the +? Then load the O. Why is it called an X with 91% confidence?
  2. In the Spreadsheet network, change the X row's two dense weights from 0.6 to 0.4 and explain why the X stops winning. In the Extended network, set the scale back to the base weights (2 and 1 instead of 3 and 1.5): the winners stay the same, but how confident is each one?
  3. Press "Shift the X one pixel". The feature maps change but the max-pool values stay at 3. That is translation tolerance from max pooling.
  4. In Part 2, set filter A to vertical Sobel and filter B to horizontal Sobel. Draw a vertical line, then a horizontal one. Which map lights up, and where are the negative values?
  5. In Part 3, train both networks, then draw a digit and press → three times. Which network changes its mind first? Tick the random-shift box, reset, retrain and repeat. Compare the ±3 px column.
