From a layer to a deep network

Why stacking f(Wx + b) bends the boundary

Each demo sets the sliders and starts training. The first shows the network with no hidden layer, which is logistic regression. It cannot solve XOR however long it trains. The next two fix that in different ways.

  1. One layer is a weighted sum and a bend

    A neuron computes w·x + b, a number that is constant along straight lines in the plane, and then passes it through an activation f. The output neuron uses the sigmoid σ, which turns the score into a probability. With no hidden layer this is exactly logistic regression: the boundary p̂ = 0.5 is the straight line w·x + b = 0.

  2. A straight line cannot separate XOR

    XOR puts class 1 in the top-right and bottom-left quadrants. Any line leaves at least one quadrant on the wrong side, so the best a linear model can do is about 50 to 75% accuracy. The algebra on the right shows the contradiction for the four corner points.

  3. Hidden neurons build new features

    Each hidden neuron draws its own line and bends it with f. Look at the thumbnails: in the XOR demo, the first-layer neurons are soft half-planes. The output neuron adds them with weights, and a sum of bent half-planes can carve out two quadrants. Stacking more layers composes these pieces again, which is the edges → shapes → objects idea.

  4. Training is gradient descent on the loss

    The loss is the negative log-likelihood, the same objective as logistic regression. Backpropagation applies the chain rule layer by layer to get ∇L for every weight. Each batch moves the weights a step of size η downhill. Adam rescales the step for each weight using running averages of past gradients.

Takeaway for students. A neural network is a stack of logistic-regression-like pieces. The hidden layers learn the features you would otherwise have to engineer by hand, such as x₁·x₂ for XOR or x₁² + x₂² for circles. The price is many more parameters, a loss surface with many valleys, and the need for held-out data to check that the fit is real.

MNIST is the same recipe

The MNIST network has 784 inputs, layers of 256 and 128 ReLU neurons, and a 10-way softmax output. It has 235,146 parameters, trained on 60,000 images. This playground has the same parts at a size you can see.

p̂ₖ = exp(sₖ) / Σⱼ exp(sⱼ) (2 classes: σ)

The learning rate is a step size

Too small and the loss creeps down for thousands of epochs. Too large and each step overshoots the valley, so the loss bounces or blows up. Good values depend on the optimizer: Adam works near 0.01 to 0.03 here, plain SGD near 0.3.

θₜ₊₁ = θₜ − η ∇L(θₜ)

Train vs test loss

training loss falls toward zero and validation loss tracks it with a small gap. With noisy data and a big network the gap widens: the network memorizes the training points. The L2 penalty shrinks weights and smooths the surface. Dropout does a similar job.

  1. Each hidden unit is one line

    Unit k computes zₖ = bₖ + wₖ₁x₁ + wₖ₂x₂. That number is zero on a straight line and grows as you move away from it. The sigmoid turns it into a soft switch: aₖ ≈ 1 on one side, aₖ ≈ 0 on the other. Unit 1, z₁ = 6 + x₁ + x₂, is on everywhere except below and to the left of the line x₂ = −x₁ − 6. Each unit is a half-plane.

  2. The output adds the switches

    The four lines enclose a diamond around the center. Inside it all four units are on, so a₁ + a₂ + a₃ + a₄ ≈ 4, and 4 − 3.1 = 0.9 gives p̂ = σ(0.9) ≈ 0.71. Cross any one line and that switch turns off: the sum drops to about 3, and 3 − 3.1 is negative, so p̂ falls below 0.5. The bias −3.1 is a vote threshold. A point is called "inner" only when all four units agree.

  3. Right answers, timid probabilities

    The hand-set network classifies every point correctly, but its weights of size 1 make gentle slopes. p̂ never rises above 0.71, so its cross-entropy is 0.43. Training finds the same idea with much larger weights, sharp edges and a loss near zero.

  4. Training rarely draws your lines

    Gradient descent starts from random weights. Any four lines that fence in the disk and leave the ring outside work equally well, so the learned lines land in different places on each run. Sometimes two units share a line, or one is pushed off the plot. Many different weights give the same predictions, which is why we judge a network by what it predicts, not by its weights.

A note on the black variable

In the Boston data, black is 1000(Bk − 0.63)², where Bk is the proportion of Black residents in the tract. The original authors built it on the assumption that this proportion affects house prices in a U-shaped way. The variable has been widely criticised for encoding that racial assumption into the model. It is kept here to match the original data and the notes.

Untick it in the feature list and compare the test metrics with and without it. The log-linear model drops it too.

Marginal effects

FeatureLinear slopeNetwork avg. slope

Change in the predicted target for one more unit of the feature, others held fixed. Linear: the coefficient on the training split. Network: the average over training rows of its local slope.

  1. Same recipe, many more parameters

    Linear regression for Zagat has 4 parameters. The network from the notes has 6,529, and it learns them from 73 restaurants. Nothing stops it from memorising the training prices. On Boston it has 7,169 parameters for 364 tracts, still far more parameters than rows.

  2. Read the loss curves like plot(history)

    Training MSE keeps falling as long as you train. Validation MSE, on rows the network never fits, falls and then flattens or turns up. The gap is overfitting. Early stopping keeps the weights from the epoch with the lowest validation loss. An L2 penalty shrinks the weights so the surface cannot bend to every point.

  3. The test set is the referee, and it is noisy

    Zagat's test set has only 23 restaurants, so the test RMSE of linear regression alone moves from about $5 to $7.50 as the split changes. One split cannot rank the models. Repeat over 20 splits: with the default settings linear regression has the lower test RMSE on 17 of the 20 Zagat splits, while on Boston, with 102 test tracts, the network beats both linear models on 17 of 20.

  4. Opening the box

    A partial-dependence curve moves one feature across its range and averages the predictions over the training rows. For linear regression it is a straight line with the coefficient as slope. Permutation importance shuffles one column of the test set and measures how much the RMSE rises: a feature the model ignores costs nothing.

Test-set metrics, as in the notes
RMSE = √( mean (ŷᵢ − yᵢ)² )
MAPE = 100 · mean |ŷᵢ − yᵢ| / yᵢ
R² = 1 − Σ(yᵢ − ŷᵢ)² / Σ(yᵢ − ȳ)²

ŷ₀ ± t₀.₉₇₅,ₙ₋ₚ · s · √(1 + h₀), h₀ = x₀ᵀ(XᵀX)⁻¹x₀
notebook shortcut: ŷ₀ ± 1.96 · s
The network and its training
ŷ = W⁽⁴⁾ReLU(W⁽³⁾ReLU(W⁽²⁾ReLU(W⁽¹⁾x + b⁽¹⁾)…)…) + b⁽⁴⁾
L(θ) = mean (ŷᵢ − yᵢ)² + λ Σ w²

Interpretation

importance j = RMSE(xⱼ shuffled) − RMSE

Takeaway for students. A network can find curves a linear model misses, as for lstat and rm in Boston. With 114 restaurants and three ratings that are nearly linear, it has little to find and much to memorise, and linear regression is hard to beat. Always compare against the linear baseline, on held-out data, over more than one split.

Try this in class

  1. Press "XOR, no hidden layer". Ask students to predict the best accuracy. The loss stalls near 0.69 and the shading stays nearly flat. Then press "XOR, one layer of 4 tanh" and watch the four quadrants appear within a few hundred epochs.
  2. On Circles, set hidden layers to 1 and neurons to 2. The boundary is a band or a wedge, never a closed loop. Raise neurons to 3 and press Reset: three lines are enough to enclose the center.
  3. Pick Spiral with 1 layer of 2 neurons and train for 1,000 epochs. Then use "Spiral, 3 layers × 8". Count parameters in the table each time and compare with the 235,146 of the MNIST network.
  4. Set noise to 50% on Moons, use 3 layers × 8 with learning rate 0.03, and train for 2,000 epochs. Training loss keeps falling while test loss turns up. Raise λ to 0.01 and reset: the gap closes.
  5. Switch to SGD and compare learning rates 0.03, 0.3 and 3 on Circles. Watch the loss curve: slow, smooth, and jagged. Then set batch size to 1 and to 100 at η = 0.3 and compare the noise in the curve.
  6. In "Write a network by hand", pin a point just outside one of the four lines and read the table: one unit has switched off and p̂ drops below 0.5. Then press "Train it instead" two or three times and compare the dashed lines with yours, and the weights in the table.
  7. In "Real data", choose Zagat and set epochs to 1,000. Training MSE keeps falling while validation MSE turns up, and the network's test RMSE ends worse than linear regression's. Tick early stopping, or set λ to 1, and compare.
  8. On Zagat, ask students to guess whether the network will beat linear regression, then press "Repeat over 20 splits". Each model's test RMSE moves by more than $2 from split to split, and linear regression wins on most splits. Repeat on Boston, where the network wins on most.
  9. On Boston, pick lstat and then rm in the partial-dependence menu and point out where the network bends and the line cannot. Then untick black, and later lstat, and compare the test metrics and the importance bars.
