Bandit vs A/B Lab

Visitors arrive one at a time and each sees one page variant. A classical A/B test splits traffic evenly, then ships the winner. A bandit shifts traffic toward the better page while it is still learning. All strategies face the same visitors, so the gap in lost conversions (regret) is a fair comparison.

From A/B tests to bandits

Explore or exploit: every visitor is both a data point and a customer

The first preset is the pink-vs-black A/B test: pink converts at 40%, black at 30%. The second uses the Karaca-style sample-size exercise (3% baseline, 0.5 point lift), where a properly powered test needs about 19,700 visitors per page. The third has no winner at all.

  1. A bandit is the simplest reinforcement-learning problem

    Reinforcement learning starts with a state, an action and a reward. Here the action is which page to show, the reward is 1 if the visitor converts, and the state is what you have learned so far: conversions and visitors per page. There is no next state to plan for, so the Bellman equation reduces to “pick the action with the highest expected reward”. The hard part is that you do not know those rewards.

  2. The fixed A/B test explores first, then exploits

    It sends n visitors to every page regardless of what it sees, then ships the page with the higher observed rate. The regret line rises steeply during the test, at a slope equal to the average gap, and goes flat if the right page ships. If the wrong page ships, the line keeps rising forever.

  3. ε-greedy and UCB mix the two all the time

    ε-greedy shows the current leader, except for a fraction ε of visitors who see a random page. Its regret never stops growing, at a rate near ε times the average gap. UCB1 shows the page with the highest optimistic estimate, mean plus an uncertainty bonus, so pages that have seen little traffic get a second look. Its bonus is cautious, so it keeps exploring longer than Thompson sampling.

  4. Thompson sampling uses Bayes, exactly as in Bayes' rule

    Each page has a Beta posterior for its conversion rate. For every visitor, draw one rate from each posterior and show the page with the largest draw. A page gets traffic in proportion to the probability that it is the best. As the posteriors narrow, traffic flows to the winner on its own. This is the “A/B test continuously; update; reallocate” idea.

prior Beta(1, 1) = uniform on [0, 1]
posterior Beta(1 + sₖ, 1 + fₖ), mean (1 + sₖ)/(2 + nₖ)
The three bandit rules
ε-greedy: random page w.p. ε, else argmax p̂ₖ
UCB1: argmax p̂ₖ + √(2 ln t / nₖ)
Thompson: θₖ ~ Beta(1+sₖ, 1+fₖ), show argmax θₖ

When the classical A/B test is still the right tool. A bandit earns more while it learns, but its data are collected adaptively: the losing page gets few visitors, so its rate is estimated poorly and naive confidence intervals are biased. Use a fixed, pre-registered A/B test when you need clean inference (an unbiased lift with a CI and a p-value for a decision memo), when the decision is a one-time ship or no-ship, when outcomes arrive late (retention, returns), or when guardrail metrics need equal samples. Use a bandit when the goal is to earn during the test: headlines, thumbnails, promotions with a short shelf life, many variants at once.

Same visitors for everyone

Each visitor carries one random number u. They convert on page k if u < pₖ. Every strategy sees the same u for visitor t, so differences in regret come from the strategy, not from luck in who showed up. This is the simulation version of a paired comparison.

convertₜ(k) = 1{uₜ < pₖ}

Real-world bandits and RL

  • Netflix thumbnail tests update posteriors live.
  • Amazon uses contextual bandits for product placement.
  • AlphaGo and data-center cooling are RL with long chains of states.

The feedback-loop caveat

A bandit only learns about the pages it shows. Practitioners warn that the same loop can entrench bias: a system that sends police where it predicted crime records more crime there. Keep some exploration and audit the data the policy itself generated.

Try this in class

  1. Press “Pink 40% vs black 30%” and replay. Ask students to predict the regret of the A/B test before it ships. With 500 visitors per page it is 500 × 0.10 = 50 conversions. Compare with Thompson sampling at the same moment.
  2. Press “Set n by power calculation”. n drops from 500 to 356, and the A/B regret falls to about 36. Then run 200 simulations and read “Picks best” for the A/B row: at 80% power the test still ships the right page nearly every time when the true gap is this large.
  3. Press “Karaca-style: 3.0% vs 3.5%”. The A/B test needs 39,486 visitors before it ships. Run 200 simulations and compare average regret. Then ask what the A/B test gives you that Thompson does not: a CI on the lift.
  4. Press “Two equal pages”. Regret is zero for every strategy, since both pages are equally good. Look at the traffic shares: Thompson drifts toward one page anyway, and the A/B test ships a random one. Which strategy lets you say “there is no difference”?
  5. Set ε to 0 and run 200 simulations on the four-variant preset. Pure greedy sometimes locks onto a bad page early and never leaves. Raise ε to 0.05 and compare “Picks best”.
