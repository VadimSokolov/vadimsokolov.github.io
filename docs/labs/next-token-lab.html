Next-Token Lab

A language model outputs P(next token | all previous tokens). In the first mode you reshape that distribution with temperature, top-k and top-p, then sample from it and compare the frequencies with the probabilities. In the second you build the table of conditional probabilities yourself from a paragraph of text.

A language model is a conditional probability

A language model is a table of conditional probabilities

The first demo is the capital-of-France example. The second shows the most common way an LLM goes wrong: a flat distribution where every candidate sounds plausible. The third trains the word model and generates at high temperature.

  1. The output is a distribution, not an answer

    For “The capital of France is”, the worked example lists P(“ Paris”) = 0.93, P(“ the”) = 0.03, P(“ a”) = 0.01, and 0.03 for everything else. The network produces a score (logit) for every token in its vocabulary, and the softmax turns the scores into these probabilities.

  2. Temperature divides the logits

    Dividing every logit by T before the softmax changes the shape and keeps the ranking. T below 1 sharpens the distribution, and T = 0 always picks the top token. T above 1 flattens it, so rare tokens get sampled more often. At T = 1 you sample from the model as trained.

  3. Top-k and top-p cut the tail

    Top-k keeps the k most likely tokens. Top-p keeps the smallest set of top tokens whose probabilities add up to at least p, so it keeps few tokens when the model is confident and many when it is not. Either way the survivors are renormalized to sum to 1.

  4. High temperature is fluent but can be wrong

    Every token on the list is grammatical, so a sample always reads well. At T = 1 the France prompt names the wrong city “Lyon” or “Marseille” about once in 100 samples. At T = 2 it does so about once in 12. When the model has no sharp answer, as with a court citation it has never seen, even T = 1 produces a confident-sounding name. That is a hallucination: plausible, fluent and false.

Softmax with temperature
P_T(w) = exp(s_w / T) / Σ_v exp(s_v / T)
s_w = ln P(w) ⇒ P_T(w) ∝ P(w)^{1/T}
Order used here (the common default)
1. divide logits by T 2. keep top k
3. keep top tokens until Σ P ≥ p 4. renormalize
Entropy and perplexity
H = −Σ_w P(w) log₂ P(w), perplexity = 2^H
perplexity ≈ “number of equally likely choices”
A bigram model, estimated from counts
P(wₜ | wₜ₋₁) = count(wₜ₋₁, wₜ) / count(wₜ₋₁)
P(sentence) = Πₜ P(wₜ | wₜ₋₁)

Takeaway for students. Every LLM answer is a draw from a conditional distribution. The probabilities come from maximum likelihood on training text, the same estimator as counting in the word model, applied by a transformer that conditions on thousands of earlier tokens instead of one. Confidence in the wording says nothing about whether the content is true, so check outputs the way you would check any model: against held-out facts.

More context, sharper rows

The bigram model sees only “is” and happily writes “the capital of Italy is Madrid.” The trigram model sees “italy is” and gets it right. Transformers push this to the whole prompt: attention lets each word look at every other word.

P(w | “is”) vs P(w | “italy is”)

Tokens become vectors

A real model does not keep a row per context. It maps words to vectors (word2vec), so “Italy” and “Spain” share what the model learns about countries. That is how it generalizes to sentences it never saw, and also how it blends facts that should stay apart.

king − man + woman ≈ queen

Where the numbers come from

The France probabilities for “ Paris”, “ the” and “ a” are from the worked example. It lumps the remaining 0.03 as “...”, and this lab splits it into six illustrative tokens. All other prompts use illustrative logits, not output from a real model.

0.93 + 0.03 + 0.01 + 0.03 = 1

Try this in class

  1. On the France prompt, press “+1,000” at T = 1. Compare the blue bars with the red marks, and ask how many samples it takes for “ Lyon” to show up once. The answer is about 1/0.006 ≈ 170.
  2. Drag T from 0 to 2.5 and read the entropy row. At T = 0 it is 0 bits. At T = 1 it is about 0.54 bits. At T = 2.5 it is about 2.6 bits, and “ Paris” drops below half.
  3. Switch to “Flip a fair coin” and set top-p to 0.40. Only “ heads” survives, so the sampler is no longer fair. Raise top-p to 0.95 and both sides come back, with two filler tokens. Top-p cuts more when the model is sure and less when it is not.
  4. In mode 2, generate four sentences with the bigram model at T = 1 and count the shaded ones. Switch to trigram and generate again. Then add a sentence to the paragraph, such as “The capital of Japan is Tokyo.”, and look at the row for “is”.
  5. Set the word model to T = 0. Every generation is the same sentence, because the model always takes the top row entry. Ask students why chatbots do not run at T = 0 by default, and when you would want them to.
