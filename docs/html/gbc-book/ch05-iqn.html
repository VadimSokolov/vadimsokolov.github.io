In the previous chapters, we established the theoretical foundations of quantile functions (Chapter 3) and the noise outsourcing theorem (Chapter 4), which guarantees that any conditional distribution \(Y \mid X\) can be represented as \(Y = G^*(U, X)\) where \(U \sim \text{Uniform}(0,1)\). The natural question is: how do we learn this function \(G^*\) from data?

The answer is the Implicit Quantile Network (IQN), introduced by Dabney et al. (2018) in the context of distributional reinforcement learning and adopted here as the core computational engine of Generative Bayesian Computation. An IQN is a neural network that takes a covariate \(x\) and a quantile level \(\tau \in (0,1)\) and outputs an estimate of the \(\tau\)th conditional quantile: \[ \hat{Q}(\tau \mid x) \approx F^{-1}_{Y \mid X=x}(\tau). \tag{5.1}\]

What makes IQN “implicit” is that \(\tau\) is treated as a continuous input rather than a fixed grid. We do not pre-specify which quantiles to learn — instead, we sample \(\tau\) uniformly during training and the network learns the entire quantile function simultaneously. This is a departure from classical quantile regression (Koenker 2005), where one fits a separate model for each quantile level.

The chapter is organized as follows. We begin with the cosine embedding that transforms the scalar \(\tau\) into a rich feature vector (Section 5.1). We then describe the full architecture and the three strategies for merging \(\tau\) with \(x\) (Section 5.2). The composite loss function follows (Section 5.3), including a comparison with the Huber quantile loss (Section 5.3.1). Training details appear in Section 5.4, followed by diagnostics for validating a trained IQN (Section 5.5) and a hyperparameter sensitivity study (Section 5.6). We present two worked examples — the motorcycle crash dataset (Section 5.7) and the Friedman function with heteroscedastic noise (Section 5.8) — before closing with exercises (Section 5.9).

5.1 Cosine Embedding of \(\tau\)

The IQN encodes the quantile level \(\tau\) in a specific way. A naive approach would concatenate \(\tau\) as a scalar feature alongside \(x\). This works but is inefficient: the network must learn the entire dependence of \(\hat{Q}\) on \(\tau\) from a one-dimensional input, which is a heavy burden on a few initial weights.

A better approach is to lift \(\tau\) into a higher-dimensional space using a cosine embedding. The idea comes from Fourier analysis: smooth functions on \([0,1]\) are well-approximated by cosine series. Since the quantile function \(F^{-1}(\tau \mid x)\) is typically smooth in \(\tau\) (for a fixed \(x\)), a cosine basis is a natural representation.

TipDefinition 5.1: Cosine Embedding

For \(\tau \in (0,1)\) and embedding dimension \(M\), the cosine embedding is \[ \varphi(\tau) = \bigl(\cos(\pi \tau \cdot 1),\; \cos(\pi \tau \cdot 2),\; \ldots,\; \cos(\pi \tau \cdot M)\bigr) \in \mathbb{R}^M. \tag{5.2}\] This 1-indexed convention follows Dabney et al. (2018) and avoids a constant first feature (\(\cos(\pi\tau\cdot 0)=1\) for all \(\tau\)), which carries no information about \(\tau\).

The embedded vector is then passed through a learned linear layer followed by ReLU: \[ \phi(\tau) = \text{ReLU}\bigl(W_\tau \, \varphi(\tau) + b_\tau\bigr) \in \mathbb{R}^d, \tag{5.3}\] where \(W_\tau \in \mathbb{R}^{d \times M}\) and \(b_\tau \in \mathbb{R}^d\) are learnable parameters. This differs slightly from Dabney et al. (2018), who apply ReLU elementwise to each cosine feature before the linear layer; our formulation applies ReLU after the linear transform, which is more expressive as the linear layer can mix frequencies before the nonlinearity.

The typical choice is \(M = 64\). Each component \(\cos(\pi \tau \cdot i)\) oscillates \(i\) times over \((0,1)\), so the embedding captures both low-frequency trends (small \(i\)) and high-frequency detail (large \(i\)) in the quantile function. The subsequent linear layer and ReLU learn a task-specific combination of these frequencies.

Why cosine and not sine? The cosine basis \(\{\cos(\pi i \tau)\}_{i=0}^{M-1}\) forms an orthonormal system on \([0,1]\) with respect to the standard inner product — it is the Type-II discrete cosine transform basis. This is the same basis used in JPEG compression and has well-known approximation-theoretic properties. Barron (1993) showed that superpositions of such basis functions achieve approximation rates of \(O(N^{-1/2})\) for functions with bounded first moments of the Fourier magnitude distribution, independent of the input dimension.

import torch
import torch.nn as nn
import numpy as np

class CosineEmbedding(nn.Module):
    """Cosine embedding for quantile level tau."""
    def __init__(self, M=64, d=256):
        super().__init__()
        self.M = M
        self.fc = nn.Sequential(nn.Linear(M, d), nn.ReLU())

    def forward(self, tau):
        # tau: scalar or (batch,) tensor
        i = torch.arange(1, self.M + 1, dtype=torch.float32)
        # cos(pi * tau * i) for i = 1, 2, ..., M  (1-indexed per Dabney et al. 2018)
        cos_features = torch.cos(torch.pi * tau * i)  # (M,) or (batch, M)
        return self.fc(cos_features)

An alternative is a linear embedding, where \(\tau\) is simply passed through a linear layer: \(\phi_{\text{lin}}(\tau) = \text{ReLU}(w \cdot \tau + b)\). This works for simple problems but struggles with non-monotone or rapidly varying quantile functions. The cosine embedding provides a richer starting representation, allowing the network to converge faster and generalize better. We compare the two in Section 5.9.

5.2 Architecture

We can now describe the full IQN architecture. The network takes two inputs — the covariate \(x \in \mathbb{R}^p\) and the quantile level \(\tau \in (0,1)\) — and outputs a scalar estimate \(\hat{Q}(\tau \mid x) \in \mathbb{R}\).

The architecture has four stages. A covariate encoder MLP maps \(x\) to a hidden representation \(h_x \in \mathbb{R}^d\), while the cosine embedding maps \(\tau\) to \(h_\tau \in \mathbb{R}^d\) of the same dimension. These are merged via the element-wise product \(h = h_x \odot h_\tau\), and further MLP layers in the output head then map \(h\) to the scalar output.

The multiplicative interaction lets \(\tau\) modulate the feature representation of \(x\), rather than merely being concatenated. The covariate encoder learns which features of \(x\) are relevant, and the quantile encoder gates these features depending on which part of the distribution we are querying. This is far more expressive than additive combination.

TipDefinition 5.2: IQN Architecture

The IQN maps \((x, \tau)\) to \(\hat{Q}(\tau \mid x)\) via \[ \hat{Q}(\tau \mid x) = g_\theta\bigl(\psi_\theta(x) \odot \phi_\theta(\tau)\bigr), \tag{5.4}\] where \(\psi_\theta : \mathbb{R}^p \to \mathbb{R}^d\) is the covariate encoder, \(\phi_\theta : (0,1) \to \mathbb{R}^d\) is the cosine-based quantile encoder, \(\odot\) denotes element-wise multiplication, and \(g_\theta : \mathbb{R}^d \to \mathbb{R}\) is the output head.

Notation note. Here \(\theta\) collects all IQN network parameters. In Chapters 1 and 10, the same role is played by \(\phi\) to avoid collision with the Bayesian parameter \(\theta\). Within this chapter no Bayesian parameters appear, so the two uses are unambiguous.

5.2.1 Multiplicative vs. Additive vs. Concatenation Merging

There are three natural ways to combine the hidden representations \(h_x \in \mathbb{R}^d\) and \(h_\tau \in \mathbb{R}^d\) before passing them to the output head. Each has a distinct inductive bias, and the choice matters for both expressiveness and training stability.

The multiplicative merge computes \(h = h_x \odot h_\tau\), where \(\odot\) denotes element-wise (Hadamard) product. This is the strategy used by Dabney et al. (2018) and is our default throughout this book. In the multiplicative scheme, each component of \(h_\tau\) acts as a gate on the corresponding component of \(h_x\). When \(h_\tau^{(j)} \approx 0\), the \(j\)th feature of \(x\) is suppressed for that quantile level; when \(h_\tau^{(j)} \approx 1\), it passes through unchanged. This gating mechanism is the same one that drives the success of attention and gating architectures more broadly. For quantile estimation, it allows the network to select different features for different parts of the distribution — the features that matter for the 5th percentile may differ from those that matter for the 95th percentile, and the multiplicative merge handles this naturally.

The additive merge computes \(h = h_x + h_\tau\). This is simpler and has a clear interpretation: the quantile level shifts the covariate representation by a fixed offset. The additive merge works well when the quantile function has a location-scale structure \(Q(\tau \mid x) = \mu(x) + \sigma(x) \cdot \Phi^{-1}(\tau)\), because the offset can capture the \(\Phi^{-1}(\tau)\) term. However, it struggles when different quantile levels require qualitatively different feature representations, because the same offset is added to every component of \(h_x\) regardless of whether that component is relevant for the current quantile level. On the motorcycle data, we observe that the additive merge tends to produce slightly wider prediction intervals in the low-variance region (\(t < 15\) ms) because it cannot selectively suppress features the way the multiplicative merge can.

The concatenation merge computes \(h = [h_x; h_\tau] \in \mathbb{R}^{2d}\), simply stacking the two vectors. This is the most general approach — it places no structural constraint on how \(\tau\) and \(x\) interact — but it doubles the dimension of the input to the output head, increasing the parameter count. In principle, concatenation can represent any function of \((h_x, h_\tau)\), including both multiplicative and additive interactions, but in practice it requires more data and more training epochs to learn these interactions from scratch. On small datasets like the motorcycle data (\(n = 133\)), concatenation tends to overfit and produce noisy quantile estimates. On larger datasets (\(n > 5{,}000\)), it performs comparably to the multiplicative merge but with roughly twice the parameters.

We recommend the multiplicative merge as the default for two reasons. First, the gating mechanism provides a strong inductive bias that the quantile level should modulate (rather than merely shift) the feature representation. Second, it keeps the parameter count the same as the additive merge while being substantially more expressive. The additive merge is a reasonable fallback for very simple problems where the distribution is approximately location-scale.

The multiplicative τ-architecture has a known failure mode on high signal-to-noise problems: the covariate encoder can fit the conditional mean so tightly that little gradient flows to the τ-embedding, causing prediction intervals to collapse. Chapter 14 documents this failure, explains the SNR diagnostic that predicts it, and provides conformal remedies. All practitioners should read that chapter before deploying IQN on real data.

class IQN(nn.Module):
    """Implicit Quantile Network.

    Args:
        xdim: dimension of input covariates
        hdim: hidden layer dimension (default 256)
        M: number of cosine embedding frequencies (default 64)
    """
    def __init__(self, xdim, hdim=256, M=64):
        super().__init__()
        self.M = M
        # Quantile encoder: cosine embedding -> linear -> ReLU
        self.fc_tau = nn.Sequential(nn.Linear(M, hdim), nn.ReLU())
        # Covariate encoder: linear -> ReLU
        self.fc_x = nn.Sequential(nn.Linear(xdim, hdim), nn.ReLU())
        # Output head after multiplicative merge
        self.head = nn.Sequential(
            nn.Linear(hdim, hdim), nn.ReLU(),
            nn.Linear(hdim, 64),   nn.Tanh(),
            nn.Linear(64, 1)
        )
        self._init_weights()

    def _init_weights(self):
        for m in self.modules():
            if isinstance(m, nn.Linear):
                nn.init.xavier_uniform_(m.weight)
                nn.init.zeros_(m.bias)

    def forward(self, x, tau):
        """
        Args:
            x:   (batch, xdim) covariate tensor
            tau: scalar float in (0, 1)
        Returns:
            (batch, 1) predicted quantile values
        """
        i = torch.arange(1, self.M + 1, dtype=torch.float32)
        h_tau = self.fc_tau(torch.cos(i * torch.pi * tau))  # (hdim,), i=1..M
        h_x = self.fc_x(x)                                  # (batch, hdim)
        h = h_x * h_tau.unsqueeze(0)                         # (batch, hdim)
        return self.head(h)                                  # (batch, 1)

We use \(d = 256\) throughout: for very low-dimensional problems (\(p \leq 3\)), \(d = 128\) suffices, while high-dimensional inputs may benefit from \(d = 512\). Three hidden layers—one in each encoder plus one in the output head—is our default, with deeper networks helping for complex functions at the cost of more training epochs. The activation choices are ReLU in the encoders, Tanh in the penultimate layer (to bound intermediate representations), and no activation on the final output since quantiles are unbounded. For \(p = 2\), the model has roughly 135K parameters—modest by modern standards but sufficient for the problems in this book.

5.3 The Three-Term Loss

Training the IQN requires a loss function that encourages the output \(\hat{Q}(\tau \mid x)\) to match the true conditional quantile \(F^{-1}_{Y|X}(\tau)\). The natural choice is the pinball loss \(\rho_\tau\) from Eq. 3.2, where \(\rho_\tau(u) = \max(\tau u, (\tau-1)u)\) and \(u = y - \hat{Q}(\tau \mid x)\) is the residual.

A proper scoring rule is a loss function that is uniquely minimized when the predicted distribution equals the true conditional distribution. A loss that is not strictly proper can be “gamed” — a miscalibrated forecast may achieve a lower loss than the truth. Minimizing the expected pinball loss over \(\tau\) yields the CRPS — the continuous ranked probability score — which is a strictly proper scoring rule (Gneiting and Raftery 2007): \[ \text{CRPS}(F, y) = 2\int_0^1 \rho_\tau\bigl(y - F^{-1}(\tau)\bigr) \, d\tau. \tag{5.5}\]

By sampling \(\tau\) uniformly during training and minimizing the pinball loss, the IQN is implicitly minimizing the CRPS. This means the IQN’s training objective is a strictly proper scoring rule, and the network has no incentive to produce miscalibrated predictions. The convergence is not instantaneous — finite training introduces estimation error — but the direction is correct.

In the GBC framework, we use a composite loss that combines three terms.

TipDefinition 5.3: GBC Composite Loss

For a training pair \((x, y)\) and a sampled quantile level \(\tau \sim \text{Uniform}(0,1)\), the GBC composite loss is \[ \mathcal{L}(x, y, \tau; \theta) = w_1 \cdot L_{\text{pinball}} + w_2 \cdot L_{\text{CRPS}} + w_3 \cdot L_{\text{MAE}}, \tag{5.6}\] where \(L_{\text{pinball}} = \rho_\tau(y - \hat{Q}(\tau \mid x))\) is the standard pinball loss, \(L_{\text{CRPS}}\) is estimated by averaging the pinball loss over multiple sampled \(\tau\) values, and \(L_{\text{MAE}} = |y - \hat{\mu}(x)|\) is the mean absolute error of a location anchor. Default weights: \((w_1, w_2, w_3) = (0.70, 0.20, 0.10)\).

Each term plays a distinct role. The pinball loss (\(w_1\)) is the primary driver: at each training step, we sample a fresh \(\tau\) and compute the asymmetric pinball penalty, so over many steps the network sees all quantile levels uniformly and implicitly optimizes the CRPS. The CRPS term (\(w_2\)) adds an explicit regularizer by sampling a small batch of \(\tau\) values (say 16) and averaging their pinball losses, reducing gradient variance compared to using a single \(\tau\) per step. The MAE anchor (\(w_3\)) keeps the median prediction well-calibrated: without it, the network may produce accurate tail quantiles but a poor point forecast, so this term encourages \(\hat{Q}(0.5 \mid x) \approx \text{median}(Y \mid X=x)\).

The weights \((0.70, 0.20, 0.10)\) work well as a default across most settings, including problems with jump discontinuities (Chapter 8), where the pinball-dominant weighting avoids having the MAE anchor pull predictions toward a blended mean near the jump boundary. For smooth, well-behaved functions, equal weights \((0.33, 0.33, 0.34)\) also work well.

The implementation also includes a monotonicity regularizer. Since the quantile function must be non-decreasing in \(\tau\), we penalize crossings: if \(\tau < 0.5\), we penalize cases where the prediction is too high (relative to the median); if \(\tau > 0.5\), we penalize cases where it is too low. This is encoded implicitly in the original IQN loss through the asymmetric monotonicity term.

def pinball_loss(y, q_hat, tau):
    """Pinball (quantile) loss.

    Args:
        y:     (batch,) true values
        q_hat: (batch,) predicted quantiles
        tau:   float in (0, 1)
    Returns:
        scalar loss
    """
    e = y - q_hat
    return torch.mean(torch.maximum(tau * e, (tau - 1) * e))


def composite_loss(model, x, y, weights=(0.70, 0.20, 0.10)):
    """GBC three-term composite loss.

    Samples tau ~ Uniform(0,1) at each call.
    """
    w1, w2, w3 = weights
    tau = torch.rand(1).item()

    # Term 1: Pinball loss at sampled tau
    q_hat = model(x, tau).squeeze(-1)
    L_pinball = pinball_loss(y, q_hat, tau)

    # Term 2: CRPS estimate (average pinball over 16 tau values)
    crps_taus = torch.rand(16)
    L_crps = 0.0
    for t in crps_taus:
        q_t = model(x, t.item()).squeeze(-1)
        L_crps = L_crps + pinball_loss(y, q_t, t.item())
    L_crps = L_crps / len(crps_taus)

    # Term 3: MAE at median (location anchor)
    q_median = model(x, 0.5).squeeze(-1)
    L_mae = torch.mean(torch.abs(y - q_median))

    return w1 * L_pinball + w2 * L_crps + w3 * L_mae

Remark. The loss function above samples \(\tau\) independently at each training step. Over the course of training with thousands of steps, every quantile level is visited many times. This is the “implicit” nature of IQN: the network never commits to a fixed grid of quantiles, yet it learns the entire quantile function. Dabney et al. (2018) showed that this uniform sampling strategy is statistically efficient in the sense that the resulting estimator converges to the true conditional quantile function under mild regularity conditions.

5.3.1 Huber Quantile Loss

The pinball loss \(\rho_\tau(u)\) is piecewise linear and therefore non-smooth at \(u = 0\). While stochastic gradient descent handles non-smooth objectives perfectly well in practice, there is a smooth alternative: the Huber quantile loss, which replaces the kink at zero with a quadratic bowl.

The motivation for smoothing is the same as in standard regression: when the residuals are close to zero, the gradient of the pinball loss jumps discontinuously from \(\tau - 1\) to \(\tau\). This can cause oscillation in the optimization trajectory, particularly in the late stages of training when the network is close to the optimum and small gradient perturbations matter. The Huber quantile loss eliminates this jump by interpolating quadratically within a narrow band \(|u| \leq \kappa\).

TipDefinition 5.4: Huber Quantile Loss

For a threshold \(\kappa > 0\) and quantile level \(\tau \in (0,1)\), the Huber quantile loss is \[ \rho_\tau^\kappa(u) = \begin{cases} \frac{1}{2\kappa} u^2 \cdot |\tau - \mathbf{1}_{u < 0}| & \text{if } |u| \leq \kappa, \\ \rho_\tau(u) - \frac{\kappa}{2} \cdot |\tau - \mathbf{1}_{u < 0}| & \text{if } |u| > \kappa. \end{cases} \tag{5.7}\] The parameter \(\kappa\) controls the width of the quadratic zone. As \(\kappa \to 0\), we recover the standard pinball loss.

When does the Huber variant help? In our experience, the answer is: rarely for the IQN. The standard pinball loss works well because the stochastic gradient from sampling \(\tau\) already introduces enough noise to smooth the optimization landscape. The Huber variant can help when training on data with very heavy tails, where large residuals dominate the gradient and the quadratic damping near zero helps the network focus on getting the bulk of the distribution right before fine-tuning the tails. On the motorcycle data, switching from pinball to Huber quantile loss (\(\kappa = 1.0\)) makes no measurable difference in CRPS (both achieve approximately 12.5 averaged over 50 train/test splits). On a synthetic heavy-tailed example with \(t_3\) errors, the Huber variant reduces CRPS by about 3–5%, a modest improvement. We use the standard pinball loss throughout this book unless otherwise noted.

5.4 Training Details

Training an IQN follows standard deep learning practice with a few GBC-specific choices. We use Adam with learning rate \(\eta_0 = 10^{-3}\) and weight decay \(10^{-4}\), together with cosine annealing from \(\eta_0\) to \(\eta_{\min} = 10^{-5}\) over \(T\) epochs. Batch sizes of 256 or 512 work well in practice, with 3000 epochs for standard problems and 5000–8000 for complex surfaces. We monitor validation CRPS for early stopping, halting if no improvement is seen for 500 epochs.

The cosine annealing schedule is important. It starts with a high learning rate for rapid exploration, then gradually reduces it to fine-tune the quantile estimates: \[ \eta_t = \eta_{\min} + \frac{1}{2}(\eta_0 - \eta_{\min})\left(1 + \cos\left(\frac{\pi t}{T}\right)\right). \tag{5.8}\]

This schedule outperforms both fixed learning rates and step-decay schedules in our experiments, particularly for the tail quantiles where precise calibration matters.

Data normalization. We always standardize both inputs and outputs before training: \[ \tilde{x} = \frac{x - \bar{x}}{s_x}, \quad \tilde{y} = \frac{y - \bar{y}}{s_y}, \] where \(\bar{x}, s_x\) and \(\bar{y}, s_y\) are the training-set means and standard deviations. After prediction, we invert the transformation: \(\hat{Q}(\tau \mid x) = s_y \cdot \hat{Q}_{\text{norm}}(\tau \mid \tilde{x}) + \bar{y}\).

Sampling \(\tau\) per mini-batch. At each training step, we sample a single \(\tau \sim \text{Uniform}(0,1)\) and apply it to the entire mini-batch. This is a pedagogical simplification: the original IQN of Dabney et al. (2018) samples \(N = 32\) independent taus per example (each example trains against a different quantile level in the same forward pass), which provides better CRPS estimation per gradient step. Our shared-\(\tau\) variant is simpler to implement and reason about, trades some per-step efficiency for lower gradient variance (all examples in the batch provide signal for the same quantile), and converges to the same solution given enough epochs. For production use cases where compute is limited, switching to \(N > 1\) taus per example is a straightforward improvement (see Exercise 5.11).

def train_iqn(X_train, y_train, epochs=3000, hdim=256, M=64,
              lr=1e-3, wd=1e-4, weights=(0.70, 0.20, 0.10), seed=42):
    """Train an IQN model.

    Args:
        X_train: (n, p) numpy array of covariates
        y_train: (n,) numpy array of responses
        epochs:  number of training epochs
        hdim:    hidden dimension
        M:       cosine embedding dimension
        lr:      initial learning rate
        wd:      weight decay
        weights: (w_pinball, w_crps, w_mae)
        seed:    random seed

    Returns:
        model, x_mean, x_std, y_mean, y_std
    """
    torch.manual_seed(seed)
    xdim = X_train.shape[1]

    # Normalize
    x_mean, x_std = X_train.mean(0), X_train.std(0) + 1e-8
    y_mean, y_std = float(y_train.mean()), float(y_train.std()) + 1e-8
    Xt = torch.tensor((X_train - x_mean) / x_std, dtype=torch.float32)
    yt = torch.tensor((y_train - y_mean) / y_std, dtype=torch.float32)

    model = IQN(xdim, hdim=hdim, M=M)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=wd)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
        optimizer, T_max=epochs, eta_min=lr * 0.01
    )

    model.train()
    for epoch in range(epochs):
        optimizer.zero_grad()
        loss = composite_loss(model, Xt, yt, weights)
        loss.backward()
        optimizer.step()
        scheduler.step()

    model.eval()
    return model, x_mean, x_std, y_mean, y_std


def predict_quantiles(model, X_test, x_mean, x_std, y_mean, y_std,
                      taus=None, n_tau=500):
    """Predict quantile function at test points.

    Args:
        model:  trained IQN
        X_test: (n_test, p) numpy array
        taus:   specific tau values, or None for uniform grid
        n_tau:  number of tau values if taus is None

    Returns:
        quantiles: (n_tau, n_test) array
        tau_grid:  (n_tau,) array
    """
    if taus is None:
        tau_grid = np.linspace(0.005, 0.995, n_tau)
    else:
        tau_grid = np.array(taus)

    Xt = torch.tensor((X_test - x_mean) / x_std, dtype=torch.float32)
    quantiles = []
    with torch.no_grad():
        for tau in tau_grid:
            q = model(Xt, float(tau)).squeeze(-1).numpy()
            quantiles.append(q * y_std + y_mean)

    return np.array(quantiles), tau_grid
Note

Implementation note. The training loop above passes the entire dataset as a single batch. For large datasets (\(n > 10{,}000\)), mini-batch training with a DataLoader is recommended. The gbc package provides gbc.iqn.IQN and gbc.train.fit_iqn with mini-batching, gradient clipping, and checkpointing built in.

5.5 Diagnostics and Validation

Training an IQN is easy; knowing whether the result is trustworthy requires diagnostics. In this section we develop four checks that every practitioner should run after fitting an IQN: Probability Integral Transform (PIT) histograms, CRPS convergence curves, quantile crossing detection, and out-of-sample coverage analysis. These diagnostics are not unique to IQN — they apply to any distributional forecast — but the IQN makes them particularly easy to compute because the quantile function is available in closed form (a single forward pass).

5.5.1 PIT Histograms

The Probability Integral Transform is the oldest and most fundamental calibration check in statistics. The idea is simple: if \(\hat{F}(\cdot \mid x_i)\) is the predicted CDF at observation \(i\), then the PIT value is \[ u_i = \hat{F}(y_i \mid x_i). \tag{5.9}\] If the model is perfectly calibrated — meaning \(\hat{F} = F\) where \(F\) is the true conditional CDF — then \(u_1, \ldots, u_n\) are i.i.d. \(\text{Uniform}(0,1)\) by the probability integral transform theorem. Deviations from uniformity reveal specific miscalibration patterns: a U-shaped histogram indicates underdispersion (prediction intervals too narrow), an inverted-U indicates overdispersion (intervals too wide), and skew indicates systematic bias.

For the IQN, computing the PIT values requires inverting the quantile function. Given a trained model \(\hat{Q}(\tau \mid x)\), we evaluate on a fine grid of \(\tau\) values and find the level at which the predicted quantile crosses the observed value: \[ \hat{u}_i = \inf\bigl\{\tau \in (0,1) : \hat{Q}(\tau \mid x_i) \geq y_i\bigr\}. \] In practice, we evaluate \(\hat{Q}(\tau \mid x_i)\) on a grid of 500 \(\tau\) values and use linear interpolation to find the crossing point.

Show code (33 lines) 
def compute_pit(model, X, y, x_mean, x_std, y_mean, y_std, n_tau=500):
    """Compute PIT values for a trained IQN.

    Args:
        model:  trained IQN
        X, y:   data arrays
        x_mean, x_std, y_mean, y_std: normalization params
        n_tau:  grid resolution

    Returns:
        pit_values: (n,) array of PIT values in (0,1)
    """
    quantiles, tau_grid = predict_quantiles(
        model, X, x_mean, x_std, y_mean, y_std, n_tau=n_tau
    )
    n = len(y)
    pit_values = np.zeros(n)
    for i in range(n):
        # Find tau where Q(tau | x_i) crosses y_i
        idx = np.searchsorted(quantiles[:, i], y[i])
        if idx == 0:
            pit_values[i] = tau_grid[0]
        elif idx >= n_tau:
            pit_values[i] = tau_grid[-1]
        else:
            # Linear interpolation
            frac = (y[i] - quantiles[idx-1, i]) / (
                quantiles[idx, i] - quantiles[idx-1, i] + 1e-10
            )
            pit_values[i] = tau_grid[idx-1] + frac * (
                tau_grid[idx] - tau_grid[idx-1]
            )
    return pit_values

5.5.2 CRPS Convergence

Monitoring the CRPS on a held-out validation set during training serves as a convergence diagnostic. Unlike the training loss — which combines three terms with potentially conflicting gradients — the validation CRPS measures the single quantity we care about: how well the predicted quantile function matches the true conditional distribution on unseen data.

A well-behaved training run shows the validation CRPS decreasing rapidly in the first 500–1000 epochs, then leveling off as the network converges. Warning signs include: the CRPS increasing after an initial decrease (overfitting), the CRPS oscillating wildly (learning rate too high or batch size too small), or the CRPS plateauing at a high value (underfitting, possibly due to insufficient model capacity).

5.5.3 Quantile Crossing Detection

A valid quantile function must be non-decreasing in \(\tau\): for \(\tau_1 < \tau_2\), we require \(\hat{Q}(\tau_1 \mid x) \leq \hat{Q}(\tau_2 \mid x)\) for all \(x\). When this property is violated, the predicted distribution is internally inconsistent. Quantile crossings are rare with the IQN architecture — the cosine embedding and multiplicative merge provide a strong inductive bias toward smoothness in \(\tau\) — but they can occur on small datasets or with poorly tuned hyperparameters.

We detect crossings by evaluating the predicted quantiles on a grid and checking the monotonicity condition. The following function counts the number and severity of crossings.

Show code (18 lines) 
def detect_crossings(model, X_test, x_mean, x_std, y_mean, y_std, n_tau=200):
    """Detect quantile crossings in a trained IQN.

    Returns:
        n_crossings: number of (test point, tau pair) violations
        max_violation: largest crossing magnitude
        frac_points: fraction of test points with at least one crossing
    """
    quantiles, tau_grid = predict_quantiles(
        model, X_test, x_mean, x_std, y_mean, y_std, n_tau=n_tau
    )
    # Check monotonicity along tau axis
    diffs = np.diff(quantiles, axis=0)  # (n_tau-1, n_test)
    violations = diffs < 0
    n_crossings = int(violations.sum())
    max_violation = float(-diffs[violations].min()) if n_crossings > 0 else 0.0
    points_with_crossing = (violations.any(axis=0)).mean()
    return n_crossings, max_violation, points_with_crossing

5.5.4 Out-of-Sample Coverage

The ultimate test of a distributional forecast is whether it covers the observed data at the nominal rate. For a nominal level \(1 - \alpha\), we compute the prediction interval \([\hat{Q}(\alpha/2 \mid x_i),\; \hat{Q}(1 - \alpha/2 \mid x_i)]\) and check whether \(y_i\) falls inside. The empirical coverage is the fraction of test points that are covered. A well-calibrated model achieves empirical coverage close to the nominal level across all \(\alpha\).

We compute coverage at several nominal levels and report the results as a coverage table. Systematic undercoverage (empirical \(<\) nominal) indicates the model is overconfident; overcoverage indicates it is too conservative. The IQN on the motorcycle data typically achieves 80–83% empirical coverage at the 90% nominal level (slightly undercovering), which can be improved to 87–88% by ensembling five independently trained models.

Show code (20 lines) 
def compute_coverage(model, X, y, x_mean, x_std, y_mean, y_std,
                     nominal_levels=(0.50, 0.80, 0.90, 0.95)):
    """Compute empirical coverage at several nominal levels.

    Returns:
        dict mapping nominal level -> empirical coverage
    """
    quantiles, tau_grid = predict_quantiles(
        model, X, x_mean, x_std, y_mean, y_std, n_tau=500
    )
    coverages = {}
    for level in nominal_levels:
        alpha = 1 - level
        lo_idx = np.argmin(np.abs(tau_grid - alpha / 2))
        hi_idx = np.argmin(np.abs(tau_grid - (1 - alpha / 2)))
        lo = quantiles[lo_idx, :]
        hi = quantiles[hi_idx, :]
        covered = ((y >= lo) & (y <= hi)).mean()
        coverages[level] = float(covered)
    return coverages

5.8 Example: Friedman Function with Heteroscedastic Noise

The motorcycle data is one-dimensional and low-noise. To stress-test the IQN on a higher-dimensional problem, we turn to a 1D slice of the Friedman function with heteroscedastic noise. The Friedman function (Friedman 1991) is a standard benchmark in the surrogate modeling literature: \[ f(x) = 10 \sin(\pi x_1 x_2) + 20(x_3 - 0.5)^2 + 10 x_4 + 5 x_5, \quad x \in [0,1]^{10}. \] Five of the ten input dimensions are active (with a nonlinear interaction between \(x_1\) and \(x_2\)), and the remaining five are inert. For this demonstration, we simplify to a 1D version to allow easy visualization while retaining the essential character of the problem: \[ Y = 10\sin(\pi x) + \sigma(x)\,\varepsilon, \quad x \sim \text{Uniform}(0, 1), \quad \varepsilon \sim N(0,1), \] where \(\sigma(x) = 1 + 3x\) introduces heteroscedastic noise that grows with \(x\). The conditional mean is a smooth sinusoidal curve, but the conditional variance increases linearly across the input domain. A good quantile model should produce narrow prediction bands near \(x = 0\) and wide bands near \(x = 1\).

# Implicit Quantile Networks {#sec-iqn}

In the previous chapters, we established the theoretical foundations of quantile functions (@sec-quantiles) and the noise outsourcing theorem (@sec-noise-outsourcing), which guarantees that any conditional distribution $Y \mid X$ can be represented as $Y = G^*(U, X)$ where $U \sim \text{Uniform}(0,1)$. The natural question is: how do we *learn* this function $G^*$ from data?

The answer is the **Implicit Quantile Network** (IQN), introduced by @dabney2018implicit in the context of distributional reinforcement learning and adopted here as the core computational engine of Generative Bayesian Computation. An IQN is a neural network that takes a covariate $x$ and a quantile level $\tau \in (0,1)$ and outputs an estimate of the $\tau$th conditional quantile:
$$
\hat{Q}(\tau \mid x) \approx F^{-1}_{Y \mid X=x}(\tau).
$$ {#eq-iqn-basic}

What makes IQN "implicit" is that $\tau$ is treated as a continuous input rather than a fixed grid. We do not pre-specify which quantiles to learn --- instead, we sample $\tau$ uniformly during training and the network learns the entire quantile function simultaneously. This is a departure from classical quantile regression [@koenker2005quantile], where one fits a separate model for each quantile level.

The chapter is organized as follows. We begin with the cosine embedding that transforms the scalar $\tau$ into a rich feature vector (@sec-iqn-cosine). We then describe the full architecture and the three strategies for merging $\tau$ with $x$ (@sec-iqn-architecture). The composite loss function follows (@sec-iqn-loss), including a comparison with the Huber quantile loss (@sec-iqn-huber). Training details appear in @sec-iqn-training, followed by diagnostics for validating a trained IQN (@sec-iqn-diagnostics) and a hyperparameter sensitivity study (@sec-iqn-hyperparams). We present two worked examples --- the motorcycle crash dataset (@sec-iqn-motorcycle) and the Friedman function with heteroscedastic noise (@sec-iqn-friedman) --- before closing with exercises (@sec-iqn-exercises).


## Cosine Embedding of $\tau$ {#sec-iqn-cosine}

The IQN encodes the quantile level $\tau$ in a specific way. A naive approach would concatenate $\tau$ as a scalar feature alongside $x$. This works but is inefficient: the network must learn the entire dependence of $\hat{Q}$ on $\tau$ from a one-dimensional input, which is a heavy burden on a few initial weights.

A better approach is to lift $\tau$ into a higher-dimensional space using a **cosine embedding**. The idea comes from Fourier analysis: smooth functions on $[0,1]$ are well-approximated by cosine series. Since the quantile function $F^{-1}(\tau \mid x)$ is typically smooth in $\tau$ (for a fixed $x$), a cosine basis is a natural representation.

::: {.callout-tip appearance="simple" title="Definition 5.1: Cosine Embedding"}
For $\tau \in (0,1)$ and embedding dimension $M$, the **cosine embedding** is
$$
\varphi(\tau) = \bigl(\cos(\pi \tau \cdot 1),\; \cos(\pi \tau \cdot 2),\; \ldots,\; \cos(\pi \tau \cdot M)\bigr) \in \mathbb{R}^M.
$$ {#eq-cosine-embedding}
This 1-indexed convention follows @dabney2018implicit and avoids a constant first feature ($\cos(\pi\tau\cdot 0)=1$ for all $\tau$), which carries no information about $\tau$.

The embedded vector is then passed through a learned linear layer followed by ReLU:
$$
\phi(\tau) = \text{ReLU}\bigl(W_\tau \, \varphi(\tau) + b_\tau\bigr) \in \mathbb{R}^d,
$$ {#eq-cosine-learned}
where $W_\tau \in \mathbb{R}^{d \times M}$ and $b_\tau \in \mathbb{R}^d$ are learnable parameters. This differs slightly from @dabney2018implicit, who apply ReLU elementwise to each cosine feature *before* the linear layer; our formulation applies ReLU after the linear transform, which is more expressive as the linear layer can mix frequencies before the nonlinearity.
:::

The typical choice is $M = 64$. Each component $\cos(\pi \tau \cdot i)$ oscillates $i$ times over $(0,1)$, so the embedding captures both low-frequency trends (small $i$) and high-frequency detail (large $i$) in the quantile function. The subsequent linear layer and ReLU learn a task-specific combination of these frequencies.

Why cosine and not sine? The cosine basis $\{\cos(\pi i \tau)\}_{i=0}^{M-1}$ forms an orthonormal system on $[0,1]$ with respect to the standard inner product --- it is the Type-II discrete cosine transform basis. This is the same basis used in JPEG compression and has well-known approximation-theoretic properties. @barron1993universal showed that superpositions of such basis functions achieve approximation rates of $O(N^{-1/2})$ for functions with bounded first moments of the Fourier magnitude distribution, independent of the input dimension.

```python
class CosineEmbedding(nn.Module):
```

## Architecture {#sec-iqn-architecture}

We can now describe the full IQN architecture. The network takes two inputs --- the covariate $x \in \mathbb{R}^p$ and the quantile level $\tau \in (0,1)$ --- and outputs a scalar estimate $\hat{Q}(\tau \mid x) \in \mathbb{R}$.

The architecture has four stages. A covariate encoder MLP maps $x$ to a hidden representation $h_x \in \mathbb{R}^d$, while the cosine embedding maps $\tau$ to $h_\tau \in \mathbb{R}^d$ of the same dimension. These are merged via the element-wise product $h = h_x \odot h_\tau$, and further MLP layers in the output head then map $h$ to the scalar output.

The multiplicative interaction lets $\tau$ *modulate* the feature representation of $x$, rather than merely being concatenated. The covariate encoder learns which features of $x$ are relevant, and the quantile encoder gates these features depending on which part of the distribution we are querying. This is far more expressive than additive combination.

::: {.callout-tip appearance="simple" title="Definition 5.2: IQN Architecture"}
The IQN maps $(x, \tau)$ to $\hat{Q}(\tau \mid x)$ via
$$
\hat{Q}(\tau \mid x) = g_\theta\bigl(\psi_\theta(x) \odot \phi_\theta(\tau)\bigr),
$$ {#eq-iqn-architecture}
where $\psi_\theta : \mathbb{R}^p \to \mathbb{R}^d$ is the covariate encoder, $\phi_\theta : (0,1) \to \mathbb{R}^d$ is the cosine-based quantile encoder, $\odot$ denotes element-wise multiplication, and $g_\theta : \mathbb{R}^d \to \mathbb{R}$ is the output head.
:::

*Notation note.* Here $\theta$ collects all IQN network parameters. In Chapters 1 and 10, the same role is played by $\phi$ to avoid collision with the Bayesian parameter $\theta$. Within this chapter no Bayesian parameters appear, so the two uses are unambiguous.

### Multiplicative vs. Additive vs. Concatenation Merging {#sec-iqn-merge}

There are three natural ways to combine the hidden representations $h_x \in \mathbb{R}^d$ and $h_\tau \in \mathbb{R}^d$ before passing them to the output head. Each has a distinct inductive bias, and the choice matters for both expressiveness and training stability.

The **multiplicative** merge computes $h = h_x \odot h_\tau$, where $\odot$ denotes element-wise (Hadamard) product. This is the strategy used by @dabney2018implicit and is our default throughout this book. In the multiplicative scheme, each component of $h_\tau$ acts as a gate on the corresponding component of $h_x$. When $h_\tau^{(j)} \approx 0$, the $j$th feature of $x$ is suppressed for that quantile level; when $h_\tau^{(j)} \approx 1$, it passes through unchanged. This gating mechanism is the same one that drives the success of attention and gating architectures more broadly. For quantile estimation, it allows the network to select different features for different parts of the distribution --- the features that matter for the 5th percentile may differ from those that matter for the 95th percentile, and the multiplicative merge handles this naturally.

The **additive** merge computes $h = h_x + h_\tau$. This is simpler and has a clear interpretation: the quantile level shifts the covariate representation by a fixed offset. The additive merge works well when the quantile function has a location-scale structure $Q(\tau \mid x) = \mu(x) + \sigma(x) \cdot \Phi^{-1}(\tau)$, because the offset can capture the $\Phi^{-1}(\tau)$ term. However, it struggles when different quantile levels require qualitatively different feature representations, because the same offset is added to every component of $h_x$ regardless of whether that component is relevant for the current quantile level. On the motorcycle data, we observe that the additive merge tends to produce slightly wider prediction intervals in the low-variance region ($t < 15$ ms) because it cannot selectively suppress features the way the multiplicative merge can.

The **concatenation** merge computes $h = [h_x; h_\tau] \in \mathbb{R}^{2d}$, simply stacking the two vectors. This is the most general approach --- it places no structural constraint on how $\tau$ and $x$ interact --- but it doubles the dimension of the input to the output head, increasing the parameter count. In principle, concatenation can represent any function of $(h_x, h_\tau)$, including both multiplicative and additive interactions, but in practice it requires more data and more training epochs to learn these interactions from scratch. On small datasets like the motorcycle data ($n = 133$), concatenation tends to overfit and produce noisy quantile estimates. On larger datasets ($n > 5{,}000$), it performs comparably to the multiplicative merge but with roughly twice the parameters.

We recommend the multiplicative merge as the default for two reasons. First, the gating mechanism provides a strong inductive bias that the quantile level should modulate (rather than merely shift) the feature representation. Second, it keeps the parameter count the same as the additive merge while being substantially more expressive. The additive merge is a reasonable fallback for very simple problems where the distribution is approximately location-scale.

::: {.callout-warning appearance="simple"}
The multiplicative τ-architecture has a known failure mode on high signal-to-noise problems: the covariate encoder can fit the conditional mean so tightly that little gradient flows to the τ-embedding, causing prediction intervals to collapse. @sec-calibration documents this failure, explains the SNR diagnostic that predicts it, and provides conformal remedies. All practitioners should read that chapter before deploying IQN on real data.
:::

```python
class IQN(nn.Module):
    """Implicit Quantile Network.

    Args:
        xdim: dimension of input covariates
        hdim: hidden layer dimension (default 256)
        M: number of cosine embedding frequencies (default 64)
    """
    def __init__(self, xdim, hdim=256, M=64):
        super().__init__()
        self.M = M
        # Quantile encoder: cosine embedding -> linear -> ReLU
        self.fc_tau = nn.Sequential(nn.Linear(M, hdim), nn.ReLU())
        # Covariate encoder: linear -> ReLU
        self.fc_x = nn.Sequential(nn.Linear(xdim, hdim), nn.ReLU())
        # Output head after multiplicative merge
        self.head = nn.Sequential(
            nn.Linear(hdim, hdim), nn.ReLU(),
            nn.Linear(hdim, 64),   nn.Tanh(),
            nn.Linear(64, 1)
        )
        self._init_weights()

    def _init_weights(self):
        for m in self.modules():
            if isinstance(m, nn.Linear):
                nn.init.xavier_uniform_(m.weight)
                nn.init.zeros_(m.bias)

    def forward(self, x, tau):
        """
        Args:
            x:   (batch, xdim) covariate tensor
            tau: scalar float in (0, 1)
        Returns:
            (batch, 1) predicted quantile values
        """
        i = torch.arange(1, self.M + 1, dtype=torch.float32)
        h_tau = self.fc_tau(torch.cos(i * torch.pi * tau))  # (hdim,), i=1..M
        h_x = self.fc_x(x)                                  # (batch, hdim)
        h = h_x * h_tau.unsqueeze(0)                         # (batch, hdim)
        return self.head(h)                                  # (batch, 1)
```

## The Three-Term Loss {#sec-iqn-loss}

Training the IQN requires a loss function that encourages the output $\hat{Q}(\tau \mid x)$ to match the true conditional quantile $F^{-1}_{Y|X}(\tau)$. The natural choice is the **pinball loss** $\rho_\tau$ from @eq-check-loss, where $\rho_\tau(u) = \max(\tau u, (\tau-1)u)$ and $u = y - \hat{Q}(\tau \mid x)$ is the residual.

A proper scoring rule is a loss function that is uniquely minimized when the predicted distribution equals the true conditional distribution. A loss that is not strictly proper can be "gamed" --- a miscalibrated forecast may achieve a lower loss than the truth. Minimizing the expected pinball loss over $\tau$ yields the CRPS --- the continuous ranked probability score --- which is a strictly proper scoring rule [@gneiting2007strictly]:
$$
\text{CRPS}(F, y) = 2\int_0^1 \rho_\tau\bigl(y - F^{-1}(\tau)\bigr) \, d\tau.
$$ {#eq-crps-integral}

By sampling $\tau$ uniformly during training and minimizing the pinball loss, the IQN is implicitly minimizing the CRPS. This means the IQN's training objective is a strictly proper scoring rule, and the network has no incentive to produce miscalibrated predictions. The convergence is not instantaneous --- finite training introduces estimation error --- but the direction is correct.

In the GBC framework, we use a *composite loss* that combines three terms.

::: {.callout-tip appearance="simple" title="Definition 5.3: GBC Composite Loss"}
For a training pair $(x, y)$ and a sampled quantile level $\tau \sim \text{Uniform}(0,1)$, the GBC composite loss is
$$
\mathcal{L}(x, y, \tau; \theta) = w_1 \cdot L_{\text{pinball}} + w_2 \cdot L_{\text{CRPS}} + w_3 \cdot L_{\text{MAE}},
$$ {#eq-composite-loss}
where $L_{\text{pinball}} = \rho_\tau(y - \hat{Q}(\tau \mid x))$ is the standard pinball loss, $L_{\text{CRPS}}$ is estimated by averaging the pinball loss over multiple sampled $\tau$ values, and $L_{\text{MAE}} = |y - \hat{\mu}(x)|$ is the mean absolute error of a location anchor. Default weights: $(w_1, w_2, w_3) = (0.70, 0.20, 0.10)$.
:::

Each term plays a distinct role. The pinball loss ($w_1$) is the primary driver: at each training step, we sample a fresh $\tau$ and compute the asymmetric pinball penalty, so over many steps the network sees all quantile levels uniformly and implicitly optimizes the CRPS. The CRPS term ($w_2$) adds an explicit regularizer by sampling a small batch of $\tau$ values (say 16) and averaging their pinball losses, reducing gradient variance compared to using a single $\tau$ per step. The MAE anchor ($w_3$) keeps the median prediction well-calibrated: without it, the network may produce accurate tail quantiles but a poor point forecast, so this term encourages $\hat{Q}(0.5 \mid x) \approx \text{median}(Y \mid X=x)$.

The weights $(0.70, 0.20, 0.10)$ work well as a default across most settings, including problems with jump discontinuities (@sec-jumps), where the pinball-dominant weighting avoids having the MAE anchor pull predictions toward a blended mean near the jump boundary. For smooth, well-behaved functions, equal weights $(0.33, 0.33, 0.34)$ also work well.

The implementation also includes a *monotonicity regularizer*. Since the quantile function must be non-decreasing in $\tau$, we penalize crossings: if $\tau < 0.5$, we penalize cases where the prediction is too high (relative to the median); if $\tau > 0.5$, we penalize cases where it is too low. This is encoded implicitly in the original IQN loss through the asymmetric monotonicity term.

```python
def pinball_loss(y, q_hat, tau):
    """Pinball (quantile) loss.

    Args:
        y:     (batch,) true values
        q_hat: (batch,) predicted quantiles
        tau:   float in (0, 1)
    Returns:
        scalar loss
    """
    e = y - q_hat
    return torch.mean(torch.maximum(tau * e, (tau - 1) * e))


def composite_loss(model, x, y, weights=(0.70, 0.20, 0.10)):
    """GBC three-term composite loss.

    Samples tau ~ Uniform(0,1) at each call.
    """
    w1, w2, w3 = weights
    tau = torch.rand(1).item()

    # Term 1: Pinball loss at sampled tau
    q_hat = model(x, tau).squeeze(-1)
    L_pinball = pinball_loss(y, q_hat, tau)

    # Term 2: CRPS estimate (average pinball over 16 tau values)
    crps_taus = torch.rand(16)
    L_crps = 0.0
    for t in crps_taus:
        q_t = model(x, t.item()).squeeze(-1)
        L_crps = L_crps + pinball_loss(y, q_t, t.item())
    L_crps = L_crps / len(crps_taus)

    # Term 3: MAE at median (location anchor)
    q_median = model(x, 0.5).squeeze(-1)
    L_mae = torch.mean(torch.abs(y - q_median))

    return w1 * L_pinball + w2 * L_crps + w3 * L_mae


# Quick check
model = IQN(xdim=1, hdim=64, M=32)
x_demo = torch.randn(16, 1)
y_demo = torch.randn(16)
loss_val = composite_loss(model, x_demo, y_demo)
print(f"Composite loss value: {loss_val.item():.4f}")
```

::: {.callout-note}
*Remark.* The loss function above samples $\tau$ *independently at each training step*. Over the course of training with thousands of steps, every quantile level is visited many times. This is the "implicit" nature of IQN: the network never commits to a fixed grid of quantiles, yet it learns the entire quantile function. @dabney2018implicit showed that this uniform sampling strategy is statistically efficient in the sense that the resulting estimator converges to the true conditional quantile function under mild regularity conditions.
:::


### Huber Quantile Loss {#sec-iqn-huber}

The pinball loss $\rho_\tau(u)$ is piecewise linear and therefore non-smooth at $u = 0$. While stochastic gradient descent handles non-smooth objectives perfectly well in practice, there is a smooth alternative: the **Huber quantile loss**, which replaces the kink at zero with a quadratic bowl.

The motivation for smoothing is the same as in standard regression: when the residuals are close to zero, the gradient of the pinball loss jumps discontinuously from $\tau - 1$ to $\tau$. This can cause oscillation in the optimization trajectory, particularly in the late stages of training when the network is close to the optimum and small gradient perturbations matter. The Huber quantile loss eliminates this jump by interpolating quadratically within a narrow band $|u| \leq \kappa$.

::: {.callout-tip appearance="simple" title="Definition 5.4: Huber Quantile Loss"}
For a threshold $\kappa > 0$ and quantile level $\tau \in (0,1)$, the **Huber quantile loss** is
$$
\rho_\tau^\kappa(u) = \begin{cases}
\frac{1}{2\kappa} u^2 \cdot |\tau - \mathbf{1}_{u < 0}| & \text{if } |u| \leq \kappa, \\
\rho_\tau(u) - \frac{\kappa}{2} \cdot |\tau - \mathbf{1}_{u < 0}| & \text{if } |u| > \kappa.
\end{cases}
$$ {#eq-huber-quantile}
The parameter $\kappa$ controls the width of the quadratic zone. As $\kappa \to 0$, we recover the standard pinball loss.
:::

When does the Huber variant help? In our experience, the answer is: rarely for the IQN. The standard pinball loss works well because the stochastic gradient from sampling $\tau$ already introduces enough noise to smooth the optimization landscape. The Huber variant can help when training on data with very heavy tails, where large residuals dominate the gradient and the quadratic damping near zero helps the network focus on getting the bulk of the distribution right before fine-tuning the tails. On the motorcycle data, switching from pinball to Huber quantile loss ($\kappa = 1.0$) makes no measurable difference in CRPS (both achieve approximately 12.5 averaged over 50 train/test splits). On a synthetic heavy-tailed example with $t_3$ errors, the Huber variant reduces CRPS by about 3--5%, a modest improvement. We use the standard pinball loss throughout this book unless otherwise noted.


## Training Details {#sec-iqn-training}

Training an IQN follows standard deep learning practice with a few GBC-specific choices. We use Adam with learning rate $\eta_0 = 10^{-3}$ and weight decay $10^{-4}$, together with cosine annealing from $\eta_0$ to $\eta_{\min} = 10^{-5}$ over $T$ epochs. Batch sizes of 256 or 512 work well in practice, with 3000 epochs for standard problems and 5000--8000 for complex surfaces. We monitor validation CRPS for early stopping, halting if no improvement is seen for 500 epochs.

The *cosine annealing* schedule is important. It starts with a high learning rate for rapid exploration, then gradually reduces it to fine-tune the quantile estimates:
$$
\eta_t = \eta_{\min} + \frac{1}{2}(\eta_0 - \eta_{\min})\left(1 + \cos\left(\frac{\pi t}{T}\right)\right).
$$ {#eq-cosine-annealing}

This schedule outperforms both fixed learning rates and step-decay schedules in our experiments, particularly for the tail quantiles where precise calibration matters.

*Data normalization.* We always standardize both inputs and outputs before training:
$$
\tilde{x} = \frac{x - \bar{x}}{s_x}, \quad \tilde{y} = \frac{y - \bar{y}}{s_y},
$$
where $\bar{x}, s_x$ and $\bar{y}, s_y$ are the training-set means and standard deviations. After prediction, we invert the transformation: $\hat{Q}(\tau \mid x) = s_y \cdot \hat{Q}_{\text{norm}}(\tau \mid \tilde{x}) + \bar{y}$.

*Sampling $\tau$ per mini-batch.* At each training step, we sample a single $\tau \sim \text{Uniform}(0,1)$ and apply it to the entire mini-batch. This is a pedagogical simplification: the original IQN of @dabney2018implicit samples $N = 32$ independent taus per example (each example trains against a different quantile level in the same forward pass), which provides better CRPS estimation per gradient step. Our shared-$\tau$ variant is simpler to implement and reason about, trades some per-step efficiency for lower gradient variance (all examples in the batch provide signal for the same quantile), and converges to the same solution given enough epochs. For production use cases where compute is limited, switching to $N > 1$ taus per example is a straightforward improvement (see @exr-multi-tau).

```python
    Args:
        X_train: (n, p) numpy array of covariates
        y_train: (n,) numpy array of responses
        epochs:  number of training epochs
        hdim:    hidden dimension
        M:       cosine embedding dimension
        lr:      initial learning rate
        wd:      weight decay
        weights: (w_pinball, w_crps, w_mae)
        seed:    random seed

    Returns:
        model, x_mean, x_std, y_mean, y_std
    """
    torch.manual_seed(seed)
    xdim = X_train.shape[1]

    # Normalize
    x_mean, x_std = X_train.mean(0), X_train.std(0) + 1e-8
    y_mean, y_std = float(y_train.mean()), float(y_train.std()) + 1e-8
    Xt = torch.tensor((X_train - x_mean) / x_std, dtype=torch.float32)
    yt = torch.tensor((y_train - y_mean) / y_std, dtype=torch.float32)

    model = IQN(xdim, hdim=hdim, M=M)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=wd)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
        optimizer, T_max=epochs, eta_min=lr * 0.01
    )

    model.train()
    for epoch in range(epochs):
        optimizer.zero_grad()
        loss = composite_loss(model, Xt, yt, weights)
        loss.backward()
        optimizer.step()
        scheduler.step()

    model.eval()
    return model, x_mean, x_std, y_mean, y_std


def predict_quantiles(model, X_test, x_mean, x_std, y_mean, y_std,
                      taus=None, n_tau=500):
    """Predict quantile function at test points.

    Args:
        model:  trained IQN
        X_test: (n_test, p) numpy array
        taus:   specific tau values, or None for uniform grid
        n_tau:  number of tau values if taus is None

    Returns:
        quantiles: (n_tau, n_test) array
        tau_grid:  (n_tau,) array
    """
    if taus is None:
        tau_grid = np.linspace(0.005, 0.995, n_tau)
    else:
        tau_grid = np.array(taus)

    Xt = torch.tensor((X_test - x_mean) / x_std, dtype=torch.float32)
    quantiles = []
    with torch.no_grad():
        for tau in tau_grid:
            q = model(Xt, float(tau)).squeeze(-1).numpy()
            quantiles.append(q * y_std + y_mean)

    return np.array(quantiles), tau_grid
```

## Diagnostics and Validation {#sec-iqn-diagnostics}

Training an IQN is easy; knowing whether the result is trustworthy requires diagnostics. In this section we develop four checks that every practitioner should run after fitting an IQN: Probability Integral Transform (PIT) histograms, CRPS convergence curves, quantile crossing detection, and out-of-sample coverage analysis. These diagnostics are not unique to IQN --- they apply to any distributional forecast --- but the IQN makes them particularly easy to compute because the quantile function is available in closed form (a single forward pass).

### PIT Histograms {#sec-iqn-pit}

The **Probability Integral Transform** is the oldest and most fundamental calibration check in statistics. The idea is simple: if $\hat{F}(\cdot \mid x_i)$ is the predicted CDF at observation $i$, then the PIT value is
$$
u_i = \hat{F}(y_i \mid x_i).
$$ {#eq-pit}
If the model is perfectly calibrated --- meaning $\hat{F} = F$ where $F$ is the true conditional CDF --- then $u_1, \ldots, u_n$ are i.i.d.\ $\text{Uniform}(0,1)$ by the probability integral transform theorem. Deviations from uniformity reveal specific miscalibration patterns: a U-shaped histogram indicates underdispersion (prediction intervals too narrow), an inverted-U indicates overdispersion (intervals too wide), and skew indicates systematic bias.

For the IQN, computing the PIT values requires inverting the quantile function. Given a trained model $\hat{Q}(\tau \mid x)$, we evaluate on a fine grid of $\tau$ values and find the level at which the predicted quantile crosses the observed value:
$$
\hat{u}_i = \inf\bigl\{\tau \in (0,1) : \hat{Q}(\tau \mid x_i) \geq y_i\bigr\}.
$$
In practice, we evaluate $\hat{Q}(\tau \mid x_i)$ on a grid of 500 $\tau$ values and use linear interpolation to find the crossing point.

```python
#| eval: true
#| code-fold: false
def compute_pit(model, X, y, x_mean, x_std, y_mean, y_std, n_tau=500):
    """Compute PIT values for a trained IQN.

    Args:
        model:  trained IQN
        X, y:   data arrays
        x_mean, x_std, y_mean, y_std: normalization params
        n_tau:  grid resolution

    Returns:
        pit_values: (n,) array of PIT values in (0,1)
    """
    quantiles, tau_grid = predict_quantiles(
        model, X, x_mean, x_std, y_mean, y_std, n_tau=n_tau
    )
    n = len(y)
    pit_values = np.zeros(n)
    for i in range(n):
        # Find tau where Q(tau | x_i) crosses y_i
        idx = np.searchsorted(quantiles[:, i], y[i])
        if idx == 0:
            pit_values[i] = tau_grid[0]
        elif idx >= n_tau:
            pit_values[i] = tau_grid[-1]
        else:
            # Linear interpolation
            frac = (y[i] - quantiles[idx-1, i]) / (
                quantiles[idx, i] - quantiles[idx-1, i] + 1e-10
            )
            pit_values[i] = tau_grid[idx-1] + frac * (
                tau_grid[idx] - tau_grid[idx-1]
            )
    return pit_values
```

### CRPS Convergence {#sec-iqn-crps-convergence}

Monitoring the CRPS on a held-out validation set during training serves as a convergence diagnostic. Unlike the training loss --- which combines three terms with potentially conflicting gradients --- the validation CRPS measures the single quantity we care about: how well the predicted quantile function matches the true conditional distribution on unseen data.

A well-behaved training run shows the validation CRPS decreasing rapidly in the first 500--1000 epochs, then leveling off as the network converges. Warning signs include: the CRPS increasing after an initial decrease (overfitting), the CRPS oscillating wildly (learning rate too high or batch size too small), or the CRPS plateauing at a high value (underfitting, possibly due to insufficient model capacity).

### Quantile Crossing Detection {#sec-iqn-crossing}

A valid quantile function must be non-decreasing in $\tau$: for $\tau_1 < \tau_2$, we require $\hat{Q}(\tau_1 \mid x) \leq \hat{Q}(\tau_2 \mid x)$ for all $x$. When this property is violated, the predicted distribution is internally inconsistent. Quantile crossings are rare with the IQN architecture --- the cosine embedding and multiplicative merge provide a strong inductive bias toward smoothness in $\tau$ --- but they can occur on small datasets or with poorly tuned hyperparameters.

We detect crossings by evaluating the predicted quantiles on a grid and checking the monotonicity condition. The following function counts the number and severity of crossings.

```python
#| code-fold: false
def detect_crossings(model, X_test, x_mean, x_std, y_mean, y_std, n_tau=200):
    """Detect quantile crossings in a trained IQN.

    Returns:
        n_crossings: number of (test point, tau pair) violations
        max_violation: largest crossing magnitude
        frac_points: fraction of test points with at least one crossing
    """
    quantiles, tau_grid = predict_quantiles(
        model, X_test, x_mean, x_std, y_mean, y_std, n_tau=n_tau
    )
    # Check monotonicity along tau axis
    diffs = np.diff(quantiles, axis=0)  # (n_tau-1, n_test)
    violations = diffs < 0
    n_crossings = int(violations.sum())
    max_violation = float(-diffs[violations].min()) if n_crossings > 0 else 0.0
    points_with_crossing = (violations.any(axis=0)).mean()
    return n_crossings, max_violation, points_with_crossing
```

### Out-of-Sample Coverage {#sec-iqn-coverage}

The ultimate test of a distributional forecast is whether it covers the observed data at the nominal rate. For a nominal level $1 - \alpha$, we compute the prediction interval $[\hat{Q}(\alpha/2 \mid x_i),\; \hat{Q}(1 - \alpha/2 \mid x_i)]$ and check whether $y_i$ falls inside. The empirical coverage is the fraction of test points that are covered. A well-calibrated model achieves empirical coverage close to the nominal level across all $\alpha$.

We compute coverage at several nominal levels and report the results as a coverage table. Systematic undercoverage (empirical $<$ nominal) indicates the model is overconfident; overcoverage indicates it is too conservative. The IQN on the motorcycle data typically achieves 80--83% empirical coverage at the 90% nominal level (slightly undercovering), which can be improved to 87--88% by ensembling five independently trained models.

```python
#| eval: true
#| code-fold: false
def compute_coverage(model, X, y, x_mean, x_std, y_mean, y_std,
                     nominal_levels=(0.50, 0.80, 0.90, 0.95)):
    """Compute empirical coverage at several nominal levels.

    Returns:
        dict mapping nominal level -> empirical coverage
    """
    quantiles, tau_grid = predict_quantiles(
        model, X, x_mean, x_std, y_mean, y_std, n_tau=500
    )
    coverages = {}
    for level in nominal_levels:
        alpha = 1 - level
        lo_idx = np.argmin(np.abs(tau_grid - alpha / 2))
        hi_idx = np.argmin(np.abs(tau_grid - (1 - alpha / 2)))
        lo = quantiles[lo_idx, :]
        hi = quantiles[hi_idx, :]
        covered = ((y >= lo) & (y <= hi)).mean()
        coverages[level] = float(covered)
    return coverages
```

## Example: Friedman Function with Heteroscedastic Noise {#sec-iqn-friedman}

The motorcycle data is one-dimensional and low-noise. To stress-test the IQN on a higher-dimensional problem, we turn to a 1D slice of the Friedman function with heteroscedastic noise. The Friedman function [@friedman1991multivariate] is a standard benchmark in the surrogate modeling literature:
$$
f(x) = 10 \sin(\pi x_1 x_2) + 20(x_3 - 0.5)^2 + 10 x_4 + 5 x_5, \quad x \in [0,1]^{10}.
$$
Five of the ten input dimensions are active (with a nonlinear interaction between $x_1$ and $x_2$), and the remaining five are inert. For this demonstration, we simplify to a 1D version to allow easy visualization while retaining the essential character of the problem:
$$
Y = 10\sin(\pi x) + \sigma(x)\,\varepsilon, \quad x \sim \text{Uniform}(0, 1), \quad \varepsilon \sim N(0,1),
$$
where $\sigma(x) = 1 + 3x$ introduces heteroscedastic noise that grows with $x$. The conditional mean is a smooth sinusoidal curve, but the conditional variance increases linearly across the input domain. A good quantile model should produce narrow prediction bands near $x = 0$ and wide bands near $x = 1$.

```python
# True mean and quantiles
xg = X_grid_f.ravel()
true_mean = 10 * np.sin(np.pi * xg)
true_sigma = 1.0 + 3.0 * xg
from scipy.stats import norm
true_q05 = true_mean + norm.ppf(0.05) * true_sigma
true_q95 = true_mean + norm.ppf(0.95) * true_sigma

fig, ax = plt.subplots(1, 1, figsize=(7, 4))
ax.scatter(x_fried, y_fried, s=6, alpha=0.3, color='gray', zorder=1)
# Predicted bands
ax.fill_between(xg, q05_f, q95_f, alpha=0.15, color='steelblue', label='90% PI (IQN)')
ax.fill_between(xg, q25_f, q75_f, alpha=0.30, color='steelblue', label='50% PI (IQN)')
ax.plot(xg, q50_f, color='steelblue', linewidth=2, label='Median (IQN)')
# True quantiles
ax.plot(xg, true_mean, 'k--', linewidth=1.5, label='True mean')
ax.plot(xg, true_q05, 'r:', linewidth=1, label='True 5%/95%')
ax.plot(xg, true_q95, 'r:', linewidth=1)
ax.set_xlabel("x")
ax.set_ylabel("y")
ax.set_title("IQN quantile fan — Friedman 1D with heteroscedastic noise")
ax.legend(fontsize=7, loc='upper left')
plt.tight_layout()
plt.show()
```

The results confirm that the IQN captures both the smooth mean function and the changing variance. Near $x = 0$, where $\sigma(x) = 1$, the 90% prediction interval is narrow and closely tracks the true 5th and 95th percentiles (red dotted lines). Near $x = 1$, where $\sigma(x) = 4$, the bands widen appropriately. The median prediction (solid blue) aligns closely with the true conditional mean (dashed black), demonstrating that the MAE anchor in the composite loss does its job of keeping the point forecast well-calibrated.

This example also illustrates a contrast with classical approaches. A standard linear quantile regression would fit parallel lines for each quantile level, completely missing the curvature of the mean function. A Gaussian process with constant noise would produce symmetric prediction bands of constant width, missing the heteroscedasticity. The IQN, by jointly learning the dependence on both $x$ and $\tau$, captures both phenomena simultaneously without any explicit structural assumptions.
