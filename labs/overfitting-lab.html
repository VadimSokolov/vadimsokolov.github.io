One dataset, many methods, one yardstick

The winner is decided by out-of-sample error

Every method has a knob that trades bias for variance. Training error always improves as the knob moves toward flexibility. Test error improves, bottoms out, then gets worse. The buttons load contrasting settings.

  1. k-nearest neighbours: local averaging

    To predict at a new x, average y over the k closest training tracts. Small k gives a wiggly fit with low bias and high variance. Large k gives a smooth fit that misses the curve. On the real Boston data, test RMSE is lowest around k = 46. With k = 1 the training RMSE is exactly 0, because each point is its own nearest neighbour.

  2. Trees: piecewise constant

    A regression tree splits x on simple rules such as "lstat < 9.7?" and predicts the training mean in each leaf. Each extra level of depth can double the number of steps. A deep tree chases individual tracts, so a new training sample gives a very different staircase.

  3. Bagging and random forests: average many trees

    Fit a deep tree to each of B bootstrap samples and average their predictions. Averaging cuts the variance and leaves the bias alone. Adding trees does not overfit: the test curve flattens instead of turning up. A random forest also samples predictors at each split. With one predictor, as here, a forest is the same as bagging.

  4. Boosting: add small trees that fix mistakes

    Start from the mean. Fit a stump to the residuals, add a shrunken copy (rate ν) to the running prediction, and repeat. The final prediction is a sum of many weak trees. Many rounds with a high rate will overfit, so M and ν are tuned together.

The yardstick
RMSE = √( (1/n) Σ (yᵢ − ŷᵢ)² ) on held-out tracts
Bias–variance split of test error at x
E(y − f̂(x))² = σ² + bias² + variance
Boosting update, residuals rᵢ = yᵢ − F(xᵢ)
F₀ = ȳ, Fₘ = Fₘ₋₁ + ν · treeₘ(x; r)

Takeaway for students. A low training error is not evidence of a good model. The benchmark table ranks methods only by error on tracts the model never saw. Tree ensembles win on tabular data of this size, and the random forest is the safe default because more trees never hurt.

Why the test curve is a U

On the left, the model is too rigid and misses the curve (bias). On the right, it bends to fit noise in this particular training sample (variance). The bottom of the U is the best trade-off. It cannot go below the noise σ.

test MSE ≈ σ² + bias² + variance

What "new training sample" shows

Each press is a new draw of training tracts from the same population. Rigid fits barely move between draws. Flexible fits jump around. The spread of the faint curves is the variance term you cannot see from one sample.

variance = E( f̂(x) − E f̂(x) )²

About this data

The tracts are simulated. The true mean is 5 + 45·e−0.075·lstat, noise SD is 4.5, and lstat is skewed like the real variable. Numbers in this lab will not match the benchmark table, which used 13 real predictors.

medv = 5 + 45·exp(−0.075·lstat) + ε, ε ~ N(0, 4.5²)

Try this in class

  1. Load "k-NN, k = 2". Training RMSE is far below test RMSE. Press "New training sample" five times and watch the faint curves scatter. Then load k = 46 and repeat.
  2. Pick Polynomial and drag the degree from 1 to 15. Ask students to predict where the test curve bottoms out. Look at the edges of the plot at degree 15.
  3. Pick Tree and set depth 1, 2, 3. Read off the first split value and compare it to the benchmark's "lstat < 9.7?" rule.
  4. Pick Forest and slide B from 1 to 300. The test curve drops and flattens without turning up. Compare with a single deep tree at the same depth.
  5. Pick Boosting, set ν = 1 and M = 1,000. Then set ν = 0.05. Same number of rounds, very different test error.
